Ericsson and VodafoneThree switch on a cloud-native 5G core built for slicing

9 Tbps packet coredual-mode 4G/5G coreMOCN to dedicated core

Ericsson and VodafoneThree have taken live a cloud-native 5G core in the United Kingdom. The core is powered by Ericsson's dual-mode 5G Core, which unifies 4G and 5G core functions on a single platform running on Ericsson's Cloud Native Infrastructure Solution, and is designed for 9 terabits per second of capacity — described as one of Europe's largest mobile packet cores. It serves 28.6 million customers.

The core is the delivery engine for differentiated connectivity: two dedicated network slices — 5G+ FastTrack for consumers and a National Business Slice — provide up to four times faster speeds and a 15 Mbps minimum download guarantee inside 5G Standalone coverage. The rollout follows an earlier world-first unification of core-level sharing through Multi-Operator Core Network (MOCN) technology over a multi-vendor 4G and 5G radio network, now evolving into a single dedicated core.

Why read it A concrete, live deployment of a cloud-native packet core whose commercial value is delivered through network slicing — the clearest current example of the core as a programmable platform rather than a fixed appliance.

Field study: 72 hours of idle Android packets behind a pfSense firewall

348.4 idle requests/hour42 endpointsCC BY 4.0 packet dataset

A research team captured 72 continuous hours of network packets from three untouched Google Pixel 8 phones on an isolated Wi-Fi network behind an enterprise pfSense firewall running Wireshark, then analyzed the traffic to Alphabet's Autonomous System Number 15169. A stock Android device generated 348.4 outbound requests per hour while idle — roughly 8,300 background transmissions per day — versus 0.0 per hour on a GrapheneOS build with no Google services.

The breakdown attributes most idle traffic to Google Play Services (142.6 requests/hour), location services uploading nearby Wi-Fi router identifiers for triangulation (84.2/hour), device provisioning of hardware fingerprints and SIM serials (48.0/hour), Photos sync tokens (28.5/hour), and a persistent push-notification heartbeat socket (14.8/hour). The raw CSV is released under a Creative Commons licence with timestamps, destination IPs, ports, and payload sizes.

Why read it A hands-on packet-capture (PCAP) study with a real dataset and reproducible test bench — useful both as a template for PCAP-driven network analysis and as evidence of what idle devices actually put on the wire.

Microsoft has released fixes for a maximum-severity vulnerability in Azure AI Foundry, tracked as CVE-2026-85889 and rated CVSS 10.0. The flaw is a missing authentication check for a critical function that allows an unauthorized attacker to elevate privileges over the network. There is no evidence of exploitation in the wild.

The fix shipped alongside other critical cloud patches, including a 9.9 command-injection flaw in Microsoft 365 Copilot (CVE-2026-85885) and a 9.9 improper-authorization flaw in Azure Database for PostgreSQL (CVE-2026-85878). As is typical for cloud CVEs, Microsoft says the issues are already mitigated server-side and require no customer action.

Why read it A reminder that the AI platform layer — gateways, agent runtimes, and model endpoints — is now first-class attack surface, and that cloud-hosted AI services can be patched without any customer action.

Anthropic's threat intelligence report for September 2026 documents eight months of disrupted misuse across cyber operations, surveillance, influence operations, conventional weapons, and biological misuse. The cyber cases are the most striking: a Russian espionage actor ran AI-driven workflows that automatically rebuilt malware whenever defenders shipped a detection, and financially motivated crews ran multi-agent frameworks that handled reconnaissance, exploitation, and exfiltration while humans only set targets and reviewed results. A separate section describes industrial-scale 'illicit distillation': the report says it detected chain-of-thought extraction campaigns by several Chinese labs, including one it attributes to Alibaba that peaked near three million exchanges per day across thousands of fraudulent accounts, plus labs that silently relayed their own users' traffic to Claude. The report recommends treating AI API keys, sandboxes, and agent integrations with the same seriousness as production credentials.

Why read it A primary-source account of how agentic AI is being used offensively, plus a new attack surface — the AI supply chain of keys, gateways, and relay services.

RAFT: a stateful retrieval framework for troubleshooting agents

entry-level retrievalstateful case trajectoriesEMNLP 2026 Industry Track

RAFT (Retrieval-Augmented Framework for Troubleshooting Agents) treats each closed support case not as a static document but as a directed chain of timeline entries, and retrieves at the entry level. This surfaces historical cases whose intermediate states match the active case and returns the parent-case trajectory anchored at the matched state; an optional case-level graph links related cases through a configurable similarity representation.

Because public multi-stage troubleshooting data is scarce, the authors pair a synthetic benchmark built from Microsoft Learn Windows Server documentation with real Apache Jira issues carrying human duplicate labels. RAFT improves Case Hit over vanilla retrieval-augmented generation (RAG) and GraphRAG baselines at every stage of case progress, with statistically significant gains over the strongest baseline. The benchmark, implementation, and evaluation set are released.

Why read it A concrete advance in structured retrieval — modelling the stateful, multi-stage nature of real troubleshooting instead of flattening cases into documents.

Which parts of a coding-agent harness actually help? A 176-configuration study

176 matched settingscontext-overflow preventionbash-only cost win

The authors fix a lightweight coding harness's execution loop and vary three components — planning, action space, and context management — across four models on SWE-Bench Verified and Terminal-Bench 2.1, evaluating 176 matched settings spanning five context-management strategies and four context-window budgets.

Findings: context management matters more as the context budget tightens, mostly by preventing context-overflow failures; staging rule-based elision before LLM-based summarization is the most efficient strategy, while making elided content recoverable adds machinery models rarely use; planning shifts from an accuracy scaffold for weaker models to a cost saver for stronger ones; and predefined tools help models with weak shell proficiency, whereas bash-capable models do fine with a bash-only interface at lower cost.

Why read it Component-level evidence for building coding-agent harnesses — useful for anyone tuning agent loops rather than swapping models.

ROCmFix: one script to fix AMD GPU overrides and benchmark Vulkan vs HIP

auto HSA overrideVulkan vs HIP benchzero install

ROCmFix is a single-file, zero-install script that auto-detects an AMD GPU, looks up the correct HSA_OVERRIDE_GFX_VERSION in a live community database, applies it to the shell configuration, and runs health diagnostics. It targets the common failure where local inference on AMD hardware throws HSA_STATUS_ERROR_INVALID_ISA or silently falls back to the CPU.

It also includes a 'bench' command that runs a short generation test against Ollama or LM Studio using Vulkan and then HIP/ROCm, reporting which backend is faster on the machine — a practical answer to the recurring Vulkan-versus-ROCm question.

Why read it Local inference on AMD hardware is still a configuration minefield; tooling that automates the overrides and measures the backends removes real friction.

Chronicle: cut-point replay turns agent incidents into regression tests

cut-point replay23 µs recording overheadbit-stable replay

Large language model agent failures are hard to reproduce because model responses are non-deterministic, tools read changing state, and multi-step trajectories rarely repeat. Chronicle records an agent run at its non-deterministic boundaries as immutable envelopes and can replay it from the record.

Its central operation, cut-point replay, serves a chosen subset of boundaries from the record and executes the complementary subset live with new code, turning a recorded incident into a regression test that runs in continuous integration. On a benchmark of six recorded failures, recording adds 23 microseconds per boundary crossing, full replay issues zero model calls and is bit-stable across 20 repetitions, and cut-point tests fail on faulty code and pass on guarded and benign changes for all six incidents.

Why read it Brings software-engineering discipline to agent reliability — reproducible regression tests for systems that are inherently non-deterministic.

Infinite-parameter LLMs: generating and adapting weights from live data

hypernetwork weight generationonline Bayesian updatefixed stored footprint

Scaling laws assume static pretraining data, but a deployed model faces a world where much of the useful information — facts a user supplies, corrections they give — arrives at run time and is normally stuffed into the prompt and discarded. This paper asks how an architecture could learn from live interaction by writing it into its weights. Taking inspiration from Mixture-of-Experts (MoE), it proposes the Infinite-Parameter LLM: a compact hypernetwork turns run-time data into a low-rank modulation of a shared base network, so feed-forward weights are generated from live data rather than stored in a fixed bank.

Where prior weight generators read the context once and freeze, the authors carry a Bayesian belief over the generator's latent code and update it online, so the effective weight is re-derived from that evolving belief as a session proceeds. The stored footprint stays fixed, yet the weights the model can compile are effectively infinite. The paper specifies an evaluation protocol that tests this against in-context learning and retrieval.

Why read it A genuinely novel architectural direction — carrying run-time knowledge in generated weights rather than the prompt, with implications for continual learning and context economy.
