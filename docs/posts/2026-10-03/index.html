Line-rate GTP-U admission control at the edge of a cloud-native 5G core

XDP/eBPF admission controlKubernetes-hosted UPFline-rate filtering

This paper presents an XDP-based design for line-rate GTP-U admission control at the edge of a Kubernetes-hosted cloud-native 5G core. The User Plane Function (UPF) data path is the performance bottleneck of virtualized cores, and the authors move admission control to the network interface layer with eXpress Data Path (XDP) so that packets are accepted or dropped before entering the host network stack.

The design targets the edge sites where a core function must run on commodity servers, showing how eBPF/XDP can protect a virtualized UPF from overload while preserving line-rate forwarding.

Why read it Directly in Viswa's sweet spot: cloud-native packet-core engineering — a concrete, measurable way to harden a Kubernetes-hosted UPF data path at the edge.

Dynamic UPF fault recovery for resilient 5G core networks

OpenAirInterface testbedapplication-layer session restorereduced downtime

This paper proposes a dynamic User Plane Function (UPF) failure detection and recovery mechanism for 5G core networks, implemented on an OpenAirInterface-based core. An application-layer session restoration mechanism re-establishes user-plane sessions after a UPF failure so latency-sensitive services survive the outage.

The experimental results show reduced downtime and service disruption compared with naive failover, addressing a practical gap in 5G core resilience as operators virtualize more of the control and user plane.

Why read it User-plane resilience is the operational side of packet-core engineering — a concrete mechanism, implemented and measured in an open-source 5G core.

Control-compute governance in agentic AI-RAN: AI agents as both controllers and workloads

LLM agents in O-RAN controlshared GPU poolcontrol-compute coupling

Agentic AI-RAN places large language model (LLM)-driven agents inside the Open RAN (O-RAN) control hierarchy, with a promising deployment that co-locates LLM inference with physical-layer (PHY) communication processing over the same accelerated compute pool for infrastructure sharing, data locality, and low control latency.

The co-location creates bidirectional control-compute coupling: the agent competes with PHY processing for compute while simultaneously issuing control decisions that steer the network. The paper studies this coupling and proposes governance mechanisms so agents can act as both controllers and workloads without destabilizing the data plane.

Why read it A genuinely novel LLM×telecom systems problem — when the network's AI controller and the network's compute load are the same resource pool, who governs the scheduler?

Commercial observability platforms lean on distributed traces, topology maps, and baseline metrics — but operators troubleshooting proprietary software are often left with only raw, unannotated text logs. LOGOS explores the extreme boundary of log-only diagnosis: how much failure propagation can be isolated using strictly raw text logs?

Anthropic

GLM-5.3 and the spread of advanced cyber capabilities

12% vs 14% exploit success64–100% harmful engagement~4-month frontier lag

Anthropic's Frontier Red Team assessed Zhipu AI's open-weight GLM-5.3 and calls it 'the most cyber-capable open-weight model released to date': it autonomously builds end-to-end exploits, succeeding in 50 of 410 ExploitBench trials (12%) versus 14% for Anthropic's gated Claude Mythos Preview — and it engaged with harmful cyber requests 64–100% of the time in simulated tests, where comparable frontier models refuse almost universally.

The report frames the risk as proliferation: unlike gated frontier models, GLM-5.3 ships open weights with minimal safeguards, putting frontier-class exploit development in the hands of anyone. A NIST Center for AI Standards and Innovation (CAISI) assessment published the same week found GLM-5.3 lags the US frontier by about four months on cyber tasks while being dramatically cheaper to run.

Why read it The first public measurement of frontier-class exploit development arriving in a freely downloadable model — a step change in the open-weights security calculus.

Aleph Alpha

Kolibri has landed: Aleph Alpha's sovereign open-weight model

78B total / 3.46B active1M contextMerlin-Arthur abstentionApache 2.0

Aleph Alpha released Kolibri, an English-German Mixture-of-Experts (MoE) transformer with 78.1B total and 3.46B active parameters, supporting up to 1M tokens of context, under Apache 2.0 on Hugging Face. It was trained on 768 B200 GPUs over 21 days on 20T pre-training tokens (21.3% German), with mid-training and long-context stages totaling nearly 24T tokens; 40 of 50 layers use a 512-token sliding window to bound decode cost.

Kolibri uses a bilingual tokenizer (UniBPE) that compresses German better than competing models, a Merlin-Arthur grounding protocol that trains the model to abstain rather than hallucinate, and exact quantile balancing for expert routing. On math, coding, grounding, and long-context benchmarks it matches models with up to four times its active parameter count, and it leads the agentic-RAG Honeypot benchmark.

Why read it A sovereign, Apache-2.0, 3.5B-active model with 1M context and a serious grounding story — a strong candidate for on-premise and regulated deployments.
Cloudflare

Clef: Cloudflare's open-source decision models and RL fine-tuning platform

non-autoregressive scoringvision encoderRL fine-tuning platformApache 2.0

Cloudflare released Clef and Clef-flash, two decision models trained in-house and served on Workers AI, fully open-sourced under Apache 2.0. Unlike text-generating large language models, decision models return typed answers with probabilities in a single pass: Clef uses a frozen Qwen backbone and a non-autoregressive scoring head that ranks valid schema choices in parallel, giving a 2.2-second end-to-end domain classification versus 4.7 seconds for a general LLM in Cloudflare's threat-intelligence workflow.

Clef adds a vision encoder and a 64k context window (Jev has 32k, text-only), is Jev-API compatible, and currently leads the Jev Decision Index. Cloudflare also announced a reinforcement learning (RL) fine-tuning service built on AI Gateway, Workers AI, Containers, and a new Trainer primitive, letting customers specialize Clef to their own decision workloads.

Why read it Decision models are becoming the fast, cheap decision layer inside agent pipelines — and now they run at the edge with a vision encoder and an RL fine-tuning path.

HyperReCo: hypergraph evidence retrieval for LLM multi-hop reasoning

hypergraph evidencen-ary relationsmulti-hop reasoning

Multi-hop question answering needs to retrieve and connect evidence across documents, but flat retrieval loses the relationships between facts. HyperReCo models evidence as a hypergraph — where a hyperedge can connect more than two evidence passages — and retrieves connected evidence for LLM multi-hop reasoning, using a re-ranking stage to score evidence jointly rather than independently.

The hypergraph formulation captures n-ary dependencies that pairwise graph retrieval misses, which is exactly the structure multi-hop questions impose on their evidence.

Why read it A structured-RAG contribution that moves beyond pairwise graphs to hyperedges — relevant to any retrieval pipeline where answers depend on relations among several facts.
arXiv

XOR-Trellis: ultra-low-complexity dequantization for LLM quantization

XOR-based dequantizationno Hadamard transformsmemory-bound inference

Quantized large language models trade memory footprint for compute during dequantization — the step that converts stored low-bit weights back to working precision, which can dominate inference cost on memory-bound hardware. XOR-Trellis reduces dequantization to ultra-low-complexity XOR and table operations and removes the Hadamard transforms used by prior trellis-quantization schemes.

The result is a quantization scheme that preserves quality while cutting the dequantization cost that often throttles local inference on CPUs and small GPUs.

Why read it Quantization is the lever that makes open-weight models run on consumer hardware — cutting the dequantization bottleneck directly improves tokens-per-second locally.

Network world models as environments for algorithm design on complex systems

world models as simulatorsiterative algorithm designaction-delayed dynamics

World models simulate an environment and predict how it changes under actions — the tool robotics uses for planning. Complex systems such as networks need the same capability because the effect of an action is not immediate: seeding a campaign or immunizing nodes against an epidemic changes little on its own; what matters is how the system unfolds over the steps that follow.

The paper treats network world models as environments for algorithm design: instead of evaluating candidate algorithms on the real system, designers evaluate them against a learned simulator, making the inherently iterative design loop cheap and safe.

Why read it A novel, genuinely useful application of world-modeling: using learned network simulators to design and evaluate network algorithms before touching the real system.
